# User Stories

После Prototype следует MVP, а после MVP — Release.

## Prototype

### US-01 — Регистрация поддержки продукта

Как оператор, я могу зарегистрировать несколько продуктов через защищённый административный API и настроить для каждого из них отдельного Telegram-бота поддержки и существующую супергруппу с включёнными топиками.

Критерии приёмки: конфигурация проверяется до активации; одна супергруппа не может быть подключена сразу к двум продуктам; при просмотре настроек через API токены ботов и другие секреты не возвращаются.

### US-02 — Подготовка супергруппы поддержки

Как оператор, я могу вручную добавить общего служебного бота и менеджеров в супергруппу продукта, чтобы команда могла работать в ней.

Критерии приёмки: у служебного бота есть права, необходимые для чтения сообщений и создания топиков супергруппы; при отсутствии прав статус настройки содержит понятное указание, что нужно исправить.

### US-03 — Начало и продолжение диалога

Как клиент, я могу написать Telegram-боту поддержки, и все мои сообщения из этого диалога попадают в один и тот же топик супергруппы поддержки.

Критерии приёмки: первое сообщение создаёт топик, а следующие попадают в тот же топик; если топик удалили, система создаёт новый. Сообщения не попадают в другой продукт и не дублируются, если Telegram повторно отправляет обновление.

### US-04 — Обмен сообщениями и файлами

Как клиент или менеджер, я могу через наш бэкенд обмениваться текстовыми сообщениями, фотографиями, документами и голосовыми сообщениями.

Критерии приёмки: подписи к фотографиям и документам сохраняются. Если сообщение нельзя передать из-за формата или размера, отправитель получает уведомление, а причина появляется в топике клиента.

### US-05 — Ответ из топика супергруппы

Как менеджер, я могу ответить клиенту прямо в его топике супергруппы, и ответ сразу приходит клиенту от Telegram-бота поддержки.

Критерии приёмки: клиенту отправляются только сообщения менеджера из его топика супергруппы. Ошибка или неизвестный результат доставки отображаются в этом же топике.

### US-06 — Проверка настройки интеграции через административный API

Как оператор, я могу через административный API проверить, готова ли Telegram-интеграция продукта к работе.

Критерии приёмки: API показывает результат каждой проверки и понятную причину ошибки. Токены, другие секреты и сообщения клиентов в ответ не попадают.

## MVP

### US-07 — Подключение аккаунта Telegram Business

Как владелец продукта, я могу подключить аккаунт Telegram Business через общего бота-коннектора платформы, чтобы супергруппа поддержки получала обращения клиентов, а ответы отправлялись от имени бизнес-аккаунта.

Критерии приёмки: после одноразового подключения аккаунт Telegram Business связывается с продуктом; наш бэкенд проверяет подключение и выданные права; аккаунт, уже подключённый к другому бизнес-боту, подключить нельзя; Telegram-бот поддержки может продолжать работать для того же продукта, но для его клиентов используются отдельные топики супергруппы; ответы, отправленные вручную из Telegram Business, наш бэкенд не отправляет клиенту повторно. В супергруппе создаются топики только для чатов, доступ к которым владелец разрешил боту-коннектору в настройках Telegram Business. Наш бэкенд не ведёт отдельный список таких чатов и обрабатывает только сообщения, которые Telegram прислал через это подключение.

### US-08 — Настройка поддержки в Shell

Как владелец продукта, я могу в Runtime MF Shell подключить Telegram-бота поддержки или аккаунт Telegram Business, указать супергруппу поддержки и увидеть, что нужно исправить, если интеграция не работает.

Критерии приёмки: Shell вызывает API нашего бэкенда; после регистрации наш бэкенд не возвращает в Shell токены и другие постоянные учётные данные Telegram.

### US-09 — Импорт менеджеров из CSV

Как владелец продукта, я могу импортировать из CSV список ожидаемых менеджеров продукта.

Критерии приёмки: некорректные строки отображаются в отчёте; адрес электронной почты не считается идентификатором Telegram; формат CSV определяется до начала реализации.

### US-10 — Приглашение и идентификация менеджеров

Как владелец продукта, я могу создавать контролируемые ссылки-приглашения или запросы на вступление и связывать присоединившийся Telegram-аккаунт с менеджером из импортированного списка.

Критерии приёмки: видны статус вступления и роль; после вступления сохраняется Telegram ID менеджера; менеджеру выдаются только необходимые права.

## Release

### US-11 — Автоматическое создание супергруппы поддержки

Как владелец продукта, я могу в Shell подключить свой Telegram-аккаунт и подтвердить вход в Telegram, после чего система автоматически создаёт супергруппу поддержки с топиками и добавляет в неё служебного бота.

### US-12 — Попытка прямого приглашения менеджеров

Как владелец продукта, я могу запросить прямое приглашение пользователей в Telegram там, где это разрешено, с использованием ссылки-приглашения как запасного варианта, если Telegram не позволяет пригласить пользователя напрямую.

Дополнительные возможности, включая отдельные тикеты, редактирование сообщений, альбомы и внутренние заметки в клиентских топиках супергруппы, пока не включены в утверждённый объём работ.
